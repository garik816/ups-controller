# UPS Controller

Контролер автозапуску та ручного керування UPS через його штатну кнопку. Один репозиторій містить прошивки для **Arduino Nano ATmega328P** і **NodeMCU v3 / ESP8266**, зі спільною логікою та єдиною версією.

Контролер читає три дискретні сигнали: `STANDBY` — наявність дежурного живлення від мережі, `ONLINE` — зелений індикатор, `BATTERY` — жовтий індикатор. Релейний контакт імітує натискання кнопки. Це продовження проєкту `ups_autostart` від 19.10.2026.

## Варіанти

| Можливість | Arduino Nano | ESP8266 |
|---|---|---|
| Автозапуск після повернення мережі | Так | Так |
| Фільтрація входів і перевірка результату | Так | Так |
| Ручне ввімкнення, вимкнення, перезапуск | Через Serial | Через вебінтерфейс |
| Налаштування автоматики | У скетчі перед збиранням | Через вебінтерфейс, збереження у flash |
| Власна точка доступу / робота через роутер | — | Так |
| Журнал подій | Serial, 115200 бод | 24 останні записи у RAM, вебінтерфейс і Serial |
| Оновлення прошивки | USB | USB або вебінтерфейс |

Сигнали індикаторів показують режим роботи. **Відсоток заряду, напруга батареї, потужність навантаження та залишковий час роботи не вимірюються.** Для них потрібні додаткові датчики або протокол зв'язку з UPS.

## Перший запуск ESP8266

1. Прошийте NodeMCU за інструкцією нижче. Перше налаштування виконайте з від'єднаним від кнопки UPS релейним контактом.
2. Підключіться до Wi-Fi **`UPS_wifi`**, пароль **`1234567890`**.
3. Відкрийте **[http://192.168.7.1](http://192.168.7.1)**. Інтернет для роботи сторінки не потрібний.
4. Вхід до панелі: користувач **`admin`**, пароль **`1234567890`**.
5. Перевірте стан входів, виберіть мережевий режим і налаштуйте автоматику. Пароль панелі можна змінити окремо від пароля точки доступу.
6. Виконайте [перевірку підключення](docs/WIRING.md) і [стендові випробування](docs/TESTING.md), після чого підключіть реле до штатної кнопки.

Назва AP, пароль AP та адреса `192.168.7.1/24` задані прошивкою. Телефон може повідомляти, що в цій Wi-Fi мережі немає інтернету: для налаштування залишайтеся підключеними до неї.

### Мережеві режими

| Режим у панелі | Поведінка |
|---|---|
| Автономний (`standalone`) | Працює тільки `UPS_wifi`; керування за адресою `192.168.7.1`. |
| Через роутер (`router`) | ESP отримує адресу від роутера через DHCP. AP працює під час підключення і вимикається через 10 с успішного зв'язку. Якщо зв'язок втрачено, AP повертається через заданий час. |
| AP + роутер (`both`) | `UPS_wifi` залишається активною одночасно з підключенням до роутера. Панель доступна з обох мереж. |

У розділі мережі можна просканувати Wi-Fi, вибрати SSID, ввести пароль і побачити отриману IP-адресу та рівень сигналу. Порожнє поле пароля зберігає попередній пароль; для відкритої мережі є окремий вибір. Типовий час увімкнення резервної AP — **30 секунд**.

LAN роутера має використовувати підмережу, яка **не перекривається з `192.168.7.0/24`**. При конфлікті контролер від'єднується від роутера, залишає `UPS_wifi` і показує повідомлення. Після виправлення підмережі збережіть мережеві параметри повторно або перезавантажте контролер ESP для нового підключення. IP власної точки доступу не змінюється. Підключення ESP до роутера не робить його інтернет-шлюзом для клієнтів `UPS_wifi`.

Автоматика UPS працює локально й не залежить від наявності роутера, інтернету або відкритої сторінки браузера.

## Керування UPS

| Команда | Що виконується |
|---|---|
| Увімкнути | Перевірка вимкненого стану → натискання кнопки → перевірка запуску. |
| Вимкнути | Перевірка працюючого стану → натискання кнопки → перевірка вимкнення. Автостарт блокується до нового циклу мережі або явного відновлення. |
| Перезапустити UPS | Вимкнення → підтвердження вимкненого стану → пауза → запуск. Якщо вимкнення не підтверджене, наступного натискання немає. |
| Скасувати | Негайне відпускання реле та скасування незавершеної операції; автоматика переходить на утримання. Це не команда вимкнення працюючого UPS. |
| Відновити автоматику | Зняття ручного утримання та повторна оцінка заданого режиму. |

Команди з невідомим або невідповідним станом входів відхиляються. Паралельні операції не накладаються. Ручний запуск від батареї типово вимкнений; його можна дозволити окремо, якщо конкретний UPS підтримує такий запуск.

**Перезавантаження контролера ESP** в системних налаштуваннях — окрема операція, яка не натискає кнопку UPS. На ESP стан спроб і ручного утримання зберігається в RTC-пам'яті для програмного, watchdog і зовнішнього reset за наявності придатного запису. Повне зникнення живлення контролера починає новий цикл. На Nano ці ознаки зберігаються лише в RAM і скидаються після перезапуску, як у початковій версії.

### Режими автозапуску

| Режим | Поведінка |
|---|---|
| Вимкнено (`disabled`) | Тільки ручні команди. |
| Після повернення мережі (`on_mains`) | Одна автоматична спроба за безперервний період STANDBY. Працюючий UPS не перемикається. Невдала спроба не повторюється. Це типовий режим. |
| Підтримувати увімкненим (`keep_on`) | Відстеження підтвердженого вимкненого стану за наявності мережі; запуск із паузою між спробами та обмеженням їх кількості. Ручне вимкнення має пріоритет. |

Обмеження спроб у `keep_on` діє на поточний цикл мережі, а не поновлюється після кожного успішного запуску. Початкове значення — **1**, дозволено **1–3**. Для нової спроби після вичерпання ліміту потрібен новий цикл мережі або явна команда користувача.

| Параметр | Типове значення |
|---|---:|
| Фільтр STANDBY | 300 мс |
| Фільтр ONLINE/BATTERY | 300 мс |
| Підтвердження вимкненого стану | 2 с |
| Затримка перед автостартом | 10 с |
| Натискання для запуску / вимкнення | 2 с / 2 с |
| Тайм-аут підтвердження результату | 15 с |
| Пауза між вимкненням і запуском при перезапуску | 10 с |
| Мінімальна пауза повторної автоматичної спроби | 60 с |
| Автостарт після ввімкнення самого контролера | Увімкнено |
| Ручний запуск без STANDBY | Вимкнено |

Порівняно з початковим скетчем, обидва індикатори мають бути вимкненими довше — типово **2 секунди**, щоб коротка пауза миготливого індикатора не сприймалася як зупинений UPS. Значення має відповідати реальній поведінці індикаторів вашої моделі. Тайм-аут перевірки має бути більшим за час підтвердження OFF, а час OFF — не меншим за фільтр індикаторів.

### Налаштування та журнал

ESP перевіряє налаштування перед записом і зберігає попередню придатну копію. Якщо основний файл пошкоджений, використовується резервна копія. Якщо обидві непридатні або сховище недоступне, автозапуск вимикається, а панель показує помилку. Для відновлення після пошкодження файлу перевірте й повторно збережіть налаштування.

Вебжурнал містить **24 останні події у RAM**. Час події — час роботи контролера від запуску, не календарний час. Після перезапуску журнал починається заново; це не постійний історичний архів.

## Підключення

| Функція | Arduino Nano | NodeMCU v3 | Типова логіка |
|---|---|---|---|
| Вхід релейного модуля | D8 | **D1 / GPIO5** | LOW — натискання, HIGH — відпущено |
| ONLINE | D9 | **D2 / GPIO4** | HIGH — активний |
| BATTERY | D10 | **D5 / GPIO14** | HIGH — активний |
| STANDBY | D11 | **D6 / GPIO12** | HIGH — мережа присутня |

Це призначення **логічних сигналів**, а не готова схема узгодження напруг. Входи ESP8266 працюють із рівнями 3,3 В. Перед перенесенням підключення з Nano потрібні вимірювання сигналів і перевірка входу `IN` релейного модуля. Подробиці та джерела: [WIRING.md](docs/WIRING.md).

Полярність входів ESP можна зберегти лише разом із режимом автозапуску **«Вимкнено»**. Виберіть цей режим, змініть потрібні полярності й збережіть; перевірте показання ONLINE/BATTERY/STANDBY, а вже потім окремо увімкніть потрібний автоматичний режим. Прошивка відхиляє зміну полярності зі збереженням увімкненої автоматики.

## Збирання в Windows / PowerShell

Потрібні Git, Python 3 та Arduino CLI. PlatformIO не використовується. Залежності зафіксовані: **Arduino CLI 1.6.0**, **Arduino AVR 1.8.8**, **ESP8266 3.1.2**, **ArduinoJson 6.21.6**.

### Встановити Arduino CLI 1.6.0

```powershell
$CliDir = Join-Path $env:LOCALAPPDATA 'Programs\ArduinoCLI'
$CliZip = Join-Path $env:TEMP 'arduino-cli-1.6.0.zip'
New-Item -ItemType Directory -Force $CliDir | Out-Null
Invoke-WebRequest 'https://github.com/arduino/arduino-cli/releases/download/v1.6.0/arduino-cli_1.6.0_Windows_64bit.zip' -OutFile $CliZip
if ((Get-FileHash $CliZip -Algorithm SHA256).Hash -ne '2769b9b282ce597db9679d8ec14d726d57004ca4205ef4d7a795bf36b6cdc9d8') { throw 'Arduino CLI checksum mismatch' }
Expand-Archive $CliZip -DestinationPath $CliDir -Force
$env:Path = "$CliDir;$env:Path"
arduino-cli version
```

Зміна `PATH` у цьому прикладі діє в поточному вікні PowerShell. Для наступних вікон додайте `$CliDir` до користувацького `PATH` або повторіть рядок із `$env:Path`.

### Завантажити та зібрати

```powershell
git clone https://github.com/garik816/ups-controller.git
cd ups-controller
pwsh -File .\tools\build.ps1 -Target esp8266 -Install
```

**Для першого збирання потрібен `-Install`.** Він встановлює ядро ESP8266 3.1.2 і ArduinoJson 6.21.6, після чого одразу збирає прошивку. Для Nano використовуйте `-Target nano -Install`, для обох плат — `-Target all -Install`.

Після успішного встановлення залежностей `-Install` можна пропускати:

```powershell
pwsh -File .\tools\build.ps1 -Target esp8266
pwsh -File .\tools\build.ps1 -Target nano
```

Для Nano з новим bootloader:

```powershell
pwsh -File .\tools\build.ps1 -Target nano -NanoProcessor atmega328
```

Типове значення — `atmega328old`, поширене серед Nano-клонів. Зафіксовані FQBN:

- Nano: `arduino:avr:nano:cpu=atmega328old` або `arduino:avr:nano:cpu=atmega328`.
- NodeMCU: `esp8266:esp8266:nodemcuv2:eesz=4M2M,baud=115200` — NodeMCU 1.0 (ESP-12E Module), flash 4 MB, LittleFS 2 MB.

Після збирання каталог `dist` містить файли з версією в назві, `manifest.json` та `SHA256SUMS`. При збиранні однієї цілі `dist` містить тільки цю ціль; попередні згенеровані пакети замінюються.

### Якщо ESP8266 не встановлюється

`Platform 'esp8266:esp8266' not found` означає, що ядро ще не встановлене. Якщо перед цим був `context deadline exceeded` під час завантаження `package_esp8266com_index.json`, установка зупинилася на мережевому запиті. Повторне збирання без `-Install` цього не виправляє.

Оновіть скрипт і повторіть установку з каталогу проєкту:

```powershell
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw 'Git update failed; check its message before continuing.' }
pwsh -File .\tools\build.ps1 -Target esp8266 -Install
```

Скрипти використовують індекс з [офіційного GitHub Release ESP8266 3.1.2](https://github.com/esp8266/Arduino/releases/tag/3.1.2), без запиту до `arduino.esp8266.com`. URL передається всім CLI-командам ESP-збирання та має пріоритет над старим URL у конфігурації. Глобальний конфігураційний файл Arduino CLI не змінюється. За потреби адресу можна перевизначити параметром `-EspIndexUrl` у PowerShell або `--esp-index-url` у Bash.

Тайм-аут мережевої бездіяльності для запуску скрипта — **180 секунд**. Власне значення можна задати через `ARDUINO_NETWORK_CONNECTION_TIMEOUT`, наприклад:

```powershell
$env:ARDUINO_NETWORK_CONNECTION_TIMEOUT = '600s'
pwsh -File .\tools\build.ps1 -Target esp8266 -Install
```

Це параметр [Arduino CLI](https://arduino.github.io/arduino-cli/1.6/configuration/), а не загальний час усієї установки. Команда запуску PowerShell — `pwsh`, без крапки перед назвою; `.\` використовується лише перед відносним шляхом скрипта.

### Прошити через USB

Спочатку знайдіть порт:

```powershell
arduino-cli board list
```

Замініть `COM11` / `COM12` на свої порти. Для результату локального збирання:

```powershell
arduino-cli upload --port COM11 --fqbn 'esp8266:esp8266:nodemcuv2:eesz=4M2M,baud=115200' --input-dir .\build\esp8266
arduino-cli upload --port COM12 --fqbn 'arduino:avr:nano:cpu=atmega328old' --input-dir .\build\arduino_nano
```

Для готових файлів із Releases, без збирання вихідного коду:

```powershell
arduino-cli upload --port COM11 --fqbn 'esp8266:esp8266:nodemcuv2:eesz=4M2M,baud=115200' --input-file .\ups-controller-1.0.0-esp8266-nodemcu.bin
arduino-cli upload --port COM12 --fqbn 'arduino:avr:nano:cpu=atmega328old' --input-file .\ups-controller-1.0.0-arduino-nano.hex
```

Назву файлу беріть із відповідного релізу. Для USB-завантаження потрібне встановлене ядро плати, навіть якщо використовуєте готовий файл. Зміна `cpu` на `atmega328` вибирає новий bootloader Nano; записувати bootloader заново не потрібно.

Serial-діагностика:

```powershell
arduino-cli monitor --port COM11 --config baudrate=115200
```

Перед наступним прошиванням закрийте монітор порту. Для Nano підтримуються символи `?` — стан, `s` — запуск, `o` — вимкнення, `r` — перезапуск UPS, `c` — скасування й утримання автоматики, `a` — відновлення автоматики.

### Відновлення доступу до ESP

Якщо втрачений пароль панелі або неправильно налаштоване підключення до роутера, відкрийте Serial ESP на **115200 бод** та надішліть рядок:

```text
network-reset
```

Натисніть Enter. Контролер поверне автономний режим `UPS_wifi`, очистить дані роутера та відновить пароль панелі `admin` / `1234567890`. **Режим UPS, таймери, полярність входів і збережений стан поточного циклу не скидаються.** Під час операції керування UPS або оновлення прошивки команда відхиляється — дочекайтеся завершення. Команди `help` і `status` показують довідку та стан ESP.

Звичайне USB-прошивання не призначене для скидання паролів: налаштування у LittleFS зберігаються. Для відновлення доступу використовуйте `network-reset`; повне стирання flash видаляє всі налаштування і для цієї операції не потрібне.

### Linux

Встановіть [Arduino CLI 1.6.0](https://github.com/arduino/arduino-cli/releases/tag/v1.6.0), Python 3 та `g++`, потім:

```bash
bash tools/build.sh --install --test
# Лише одна прошивка після встановлення залежностей:
bash tools/build.sh --target esp8266
bash tools/build.sh --target nano --nano-processor atmega328old
```

`--test` запускає перевірки спільного автомата на комп'ютері, а для `all`/`esp8266` — також перевірки налаштувань і збереження з реальною бібліотекою ArduinoJson. Її шлях визначається через Arduino CLI. Для `nano` ArduinoJson не потрібний. Для звичайного збирання прошивки `g++` на хості не потрібний. У PowerShell еквівалент — параметр `-Test` за наявності `g++` у `PATH`.

### Arduino IDE

1. Встановіть відповідне ядро. Для ESP8266 додайте до Additional Boards Manager URLs: `https://github.com/esp8266/Arduino/releases/download/3.1.2/package_esp8266com_index.json`.
2. Скопіюйте каталог `libraries/UpsControl` до `libraries` вашого Arduino Sketchbook. Для ESP встановіть ArduinoJson **6.21.6**.
3. Для ESP після зміни сторінки виконайте `python tools/embed_web.py`. Відкрийте тільки потрібний скетч: `firmware/esp8266/esp8266.ino` або `firmware/arduino_nano/arduino_nano.ino`.
4. Виберіть NodeMCU 1.0 (ESP-12E Module), Flash Size **4MB (FS:2MB OTA:~1019KB)**; або Nano / відповідний процесор та bootloader.
5. Зберіть і завантажте. Не кладіть обидва скетчі в одну папку: Arduino об'єднує всі `.ino` одного каталогу.

Вебсторінка упакована в прошивку; окремо завантажувати образ LittleFS для неї не потрібно. LittleFS використовується для налаштувань.

## Оновлення ESP через вебінтерфейс

У системному розділі виберіть `.bin` для **ESP8266 NodeMCU**, дочекайтеся завершення завантаження і перезапуску контролера. Файл Nano `.hex` для цього не підходить. Під час операції UPS має бути в стабільному стані: прошивка відхиляє оновлення, якщо виконується натискання кнопки або інша операція керування. Перше прошивання виконується через USB.

## GitHub Actions і релізи

Workflow [Build firmware](.github/workflows/firmware.yml) працює на **GitHub-hosted `ubuntu-latest` і `windows-latest`**:

- запускає native-тести автомата та налаштувань;
- збирає Nano й ESP8266;
- перевіряє узгодженість версії та формує `.hex`, `.bin`, manifest і SHA-256;
- зберігає артефакт `ups-controller-firmware` на 30 днів;
- окремо встановлює залежності та збирає обидві плати на Windows через `tools/build.ps1 -Target all -Install`, з артефактом `ups-controller-firmware-windows`;
- при push тегу `vX.Y.Z`, який відповідає `VERSION`, публікує файли в GitHub Release після успішної збірки.

На Linux ядра та бібліотеки кешуються між запусками. Windows перевіряє установку без кеша. Реліз чекає обидві збірки й публікує основний Linux-артефакт. Файли релізу зберігаються окремо від тимчасових Actions-артефактів.

При оновленні змінюйте `VERSION`, `UPS_FIRMWARE_VERSION` у `libraries/UpsControl/src/FirmwareVersion.h`, `version` у `libraries/UpsControl/library.properties` та журнал змін разом. Обидві прошивки повинні мати один номер версії.

## Структура

| Шлях | Призначення |
|---|---|
| `firmware/arduino_nano` | Скетч і призначення входів Arduino Nano |
| `firmware/esp8266` | Wi-Fi, HTTP API, налаштування, OTA та апаратні параметри ESP |
| `libraries/UpsControl` | Спільний автомат керування без залежності від Wi-Fi |
| `web/index.html` | Автономний український вебінтерфейс |
| `tools/embed_web.py` | Детерміноване вбудовування вебсторінки у прошивку |
| `tools/build.ps1`, `tools/build.sh` | Збирання та пакування |
| `tools/run_native_tests.py` | Перевірки автомата й збереження налаштувань на комп'ютері |
| `tests` | Перевірки логіки на комп'ютері |
| `docs/API.md` | Контракт HTTP API |
| `docs/WIRING.md` | Вимоги до електричного підключення |
| `docs/TESTING.md` | Перевірки перед експлуатацією |
