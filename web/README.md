# Веб-інтерфейс ESP8266

`index.html` містить усі стилі, українські тексти та JavaScript. Інтерфейс працює
без інтернету; сторонні шрифти, бібліотеки та зовнішні ресурси не завантажуються.
Під час підготовки прошивки сторінка стискається gzip та вбудовується у flash.
Залежності Node.js на ESP8266 не потрібні.

Контракт запитів описаний у [docs/API.md](../docs/API.md). Інтерфейс перевіряє
очевидні помилки форми, але остаточне рішення щодо команди, сигналів і збереження
налаштувань приймає прошивка. Імена Wi-Fi та повідомлення журналу вставляються як
текст; порожнє поле пароля роутера зберігає попередній пароль.

## Напруга акумулятора

На вкладці «Огляд» окрема картка показує усереднену напругу акумулятора з одним
знаком після коми та код АЦП. Вона незалежна від цифрового індикатора `BATTERY`.
Вимірювання початково вимкнене. Після підключення дільника за
[схемою](../docs/WIRING.md) його можна ввімкнути в розділі «Система».

Налаштування містять масштаб перерахунку та необов'язковий поріг попередження.
Профіль має відповідати виконанню A0 і встановленому зовнішньому дільнику:

| Зовнішні резистори | NodeMCU зі штатними 220 кОм / 100 кОм | АЦП 0–1 В без штатного дільника |
|---|---:|---:|
| 180 кОм / 10 кОм | 62,6 В | 19 В |
| 220 кОм / 10 кОм | 75,8 В | 23 В |

Власний або відкалібрований масштаб допускається в межах **10–100 В** і не
замінюється пресетом під час оновлення статусу або завантаження налаштувань.
Вибір іншого профілю явно підставляє його номінальний масштаб; зміни потрібно
зберегти. Ці числа описують перерахунок коду АЦП, **не допустиму напругу підключення**:
схема проєкту розрахована на 0–16 В. Калібрування за мультиметром відправляє
контрольне значення на `/api/battery/calibrate`; остаточну перевірку та запис
виконує прошивка. Перед калібруванням потрібно зберегти зміни вимірювання.

Під час усереднення, застарівання даних, нульового сигналу або насичення АЦП
напруга приховується, а причина відображається текстом. Нульовий сигнал не
вважається доказом відсутності акумулятора. Попередження про низьку напругу
не вимикає UPS. Відсоток заряду та залишковий час роботи не розраховуються.

## Перевірка у справжньому браузері

Необов'язковий тест `tests/test_web.cjs` потребує Playwright із встановленим
Chromium на комп'ютері розробника. Запуск із кореня репозиторію:

```sh
npm install --no-save --package-lock=false playwright
npx playwright install chromium
node tests/test_web.cjs
```

Тест локально імітує HTTP API; справжній UPS не використовується. Перевіряються
команди, підтвердження вимкнення, блокування несумісних дій, оновлення токена після
скидання, збереження пароля роутера, пошук мереж, небезпечні символи в SSID і
журналі, напруга акумулятора та помилкові покази, профілі зовнішніх дільників
180 кОм і 220 кОм, збереження власного масштабу до 100 В,
калібрування й відхилення його сервером, відхилення прошивки, відновлення зв'язку
та адаптивна верстка. Оновлення параметрів вимірювання не стирає незбережені
поля інших форм.

За потреби можна передати:

- `UPS_CHROMIUM_EXECUTABLE` — шлях до встановленого виконуваного файла Chromium.
- `UPS_CHROMIUM_MODULE` — шлях до ES-модуля дистрибутива `@sparticuz/chromium`,
  якщо стандартний браузер Playwright недоступний.
- `UPS_SCREENSHOT_DIR` — директорія для контрольних знімків екрана, наприклад
  `build/ui-smoke`.

Тест не перевіряє електричні входи, справжній Wi-Fi або запис flash. Для цього
потрібна апаратна перевірка прошивки на NodeMCU.
